# 换个搭档 · 羽毛球双打排赛

纯 HTML、CSS 和 JavaScript 应用。无需安装依赖。

所有屏幕统一使用手机单列布局。宽屏居中显示，界面最大宽度为 480px。名单与设置、赛程与复制通过页签切换，底部主操作栏与界面等宽。

默认只需校对名单、场地数和可打球时长。活动名称、时间、平均每场用时、手动轮数与备注保留在“更多设置”中。完整群文本可展开预览。

新活动默认使用一块场地。已有草稿和导入备份保留原来的场地设置。

生成或恢复赛程后，默认展示全部轮次，并滚动定位当前未完成轮次。可用上一轮、下一轮和进行中按钮快速切换；每块场地独立显示双方队伍。底部主按钮完成当前轮次，旁边提供赛程分享链接。共享只读模式只提供分享和查看。名单搜索只影响显示，不改变参赛人数与排赛名单。

在线使用：[GitHub Pages](https://knoxhuang.github.io/badminton-doubles/)。

生成后点击“复制赛程分享链接”，发给其他人即可查看同一份只读快照，无需登录或导入。快照包含完整对阵及分享时进度，后续更改需重新分享。链接持有者都能查看；链接不包含原始接龙。打开快照不会读取或覆盖接收者的本机草稿。链接过长时会提示改用备份文件，微信内打开的实际链接长度兼容性需真机验证。所有数据仍无需上传数据库。

打开 `index.html` 即可使用。也可在本目录运行 `npm start`，访问 http://127.0.0.1:4173 。

1. 粘贴微信接龙，点击「识别名单」。
2. 校对参赛者；同名和多人报名需要手动确认。
3. 设置场地数和平均每场用时，按活动时长预排赛程。
4. 复制完整赛程或单轮通知，手动发送到微信群。

页面和群通知不展示轮空信息。采用搭档轮转，每轮全部结束后，再进入下一轮。新建八人、两块场地的赛程时，前七轮每个人会与另外七人各搭档一次，之后开始下一轮搭档循环。八人、一块场地时，需要十四轮。

人数和场地可整齐分组时，使用完整搭档轮转表。其他情况在均衡上场的前提下优先安排未搭档球友，无法保证最少轮数完成覆盖。自动模式会在时间估算基础上继续补足预排中的搭档覆盖，最多500轮。手动模式保持指定轮数。界面显示每人的搭档覆盖进度及所需轮次下限。活动提前结束、手动轮数不足或达到单次轮数上限时，不能保证实际打遍所有搭档。

补轮会接着已有赛程继续；更换名单或保留旧赛程时，优先补齐尚未搭档的组合。旧版未完成赛程会提示重新生成，已完成的轮次保持不变。

标记完成的轮次会锁定。临时加入、退出或调整场地后，只重排后续轮次。已参赛者退出后保留历史记录。撤销最近 20 次操作；撤销记录不会跨刷新保留。

最多支持 64 人、16 块场地、500 轮。草稿保存在当前浏览器，可导入或导出 JSON 备份。浏览器禁用存储时需要主动导出。直接打开文件时，存储和剪贴板权限由浏览器决定；自动复制失败会选中文本供手动复制。

不接入微信，不上传名单，不自动发群。无需填写性别或水平。时间可从常见范围格式中识别，具体日期与地点需手动填写。

运行测试：`npm test`（Node.js 18 或更新版本）。

手机回归：`npm run test:mobile`；流程回归：`npm run test:workflow`。浏览器检查需已有 Playwright 和 Chrome，可通过 `PLAYWRIGHT_MODULE_PATH`、`CHROME_EXECUTABLE_PATH` 指定位置。测试使用独立的临时浏览器上下文，不访问用户浏览器草稿。

## GitHub Pages 发布

源码保存在 `main` 分支，GitHub Pages 从 `gh-pages` 分支根目录发布。`.nojekyll` 用于直接托管静态文件，无需构建。

后续更新在 `main` 提交，运行测试后推送：

```sh
npm run release -- 1.0.1
git add package.json index.html version.json
git commit -m "release: v1.0.1"
git push origin main
git push origin main:gh-pages
```

每次发布先递增版本号，再提交生成的改动。`release` 命令同步 package.json、顶部版本号、静态资源查询参数和 version.json。页面会检查线上版本；也可在页尾点击“检查更新”。检查失败时只报告当前版本，不会显示“最新”。刷新到新版会保留本机草稿。

此项目是公开仓库。报名信息在访问者自己的浏览器处理，草稿不会上传到 GitHub。

轮数默认按活动时长和平均每场用时估算。识别接龙时间后会填入活动时长；也可直接修改分钟数。预排轮数包含备用，到时间即可停止，无需打完。每人预计场次按正常轮数估算。可切换手动轮数。赛程支持补充 4 轮，保留全部现有对阵；自动模式剩余不超过 2 轮时，标记完成会自动补轮。修改时间设置后需重新生成赛程。

默认假设每场 15 分钟（含换场和短休），可修改。预计轮数向上取整，另加至少 4 轮、或预计轮数的 25% 作为备用。例如 120 分钟按每场 15 分钟估算，预计打 8 轮，预排 12 轮。多块场地同时比赛计为同一轮。预排不是精确的时间表。

活动时间范围用于群通知，可打球时长用于排轮。自动模式下，可打球时长不能超过活动时间范围；扣除热身和休息时，群通知会分别显示两者。新接龙未识别到时间时，会提示沿用已有设置；该提示随草稿和备份保存，手动核对并编辑时间或时长后解除。

手机页签分别记住滚动位置。完成本轮后保持阅读位置，下一轮在原位切换为进行中，并通过整块背景、边框和状态标签突出显示。生成、恢复赛程及主动点击轮次导航时才滚动定位。文本复制范围独立设置。提示可关闭，辅助按钮的触控区域至少为 44×44px。修改姓名不会重建正在交互的名单控件。
